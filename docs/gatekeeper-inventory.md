# The gatekeeper inventory

The audit behind [DR-111](../specs/decisions/111-the-core-coordinates-as-git-does.md): every gate, reservation, claim, blocker, busy refusal and in-memory holder of a file fact in the core at commit 9766578a (the archived review rounds' tip), read in three sweeps, with its disposition under the decision's rules.
The dispositions are the implementation's plan, confirmed or corrected task by task; the specs, not this file, state the behavior.

| Disposition | Meaning |
| --- | --- |
| removed | no replacement: no race remains once the write it protected is versioned or appended |
| becomes a versioned write | the write names the version it read (bytes digest, recorded instance, clone commit, or the value read) and is refused as a conflict when it changed |
| becomes an append | the file is append-only and merges by sequence |
| becomes a file-derived read | the fact is read from the file at use; no mirror |
| stays: root lease | one process per home, kept |
| stays: instant of the write | a lock or a no-replace rename held for the instant of one write, kept |

### Reader's notes

Findings from reading the code at 9766578a (the worktree was left unchanged):

1. Latched diagnostics (#43). A blocking `refreshProblem` (space.ts:1649) is cleared only at the start of a later Refresh (1646), but the admission check at 1231 refuses every sync of that clone first. A blocking `repairFailure` is checked at 1231 before `repairIfMarked` (1233) could clear it. Each refuses the clone's syncs until a core restart, even after the file is fixed or the marker removed.

2. Lost update in `prefs.json` today (stateful case 10, #45). Apply rewrites `prefs.json` directly (storage-git.ts:371-374), while the store saves its in-memory Map whole (store.ts:691-696) and re-reads it only at Refresh's `store.reload()` (space.ts:1653). Another clone's concurrent sync calling `setPref` in between restores the viewed markers that Apply cleared.

3. `pairJoined` ends a join unpaired. When its hold fails, `pairJoined` returns (space.ts:2927) and `runJoin` then deletes the join (2906), so the join ends unpaired with no stop shown. This contradicts space-63 ("ends only once the code is cloned and paired or its clone has failed").

4. `renameOwn` reads its key list too early (plausible, not tested). The list is read at 2297-2299, before its awaits (2320-2335), and is not read again at the move (2339), unlike `moveInSync` (3185). `project.add` is not in `SPACE_GATED_COMMANDS` (service.ts:246-254), so a working folder added during those awaits would leave its clone under the old own-group folder.

5. The collision check is not part of the rename. `moveCollides` (space.ts:266-270) runs `existsSync`, then `renameSync` follows (293-311), and rename(2) replaces an empty target directory. A no-replace rename would make the check and the write one act (#47).

6. A cancel can still store a token. A cancel after the `isSettled` check (git-host.ts:455) but before `completeSignIn`'s `credentials.write` (718-720) still stores the token (#29).

7. A refresh can restore a removed token. `runRefresh` writes the rotated pair unconditionally (git-host.ts:775), so a refresh answered after a sign-out's remove brings the credential file back (#49).

8. Spec drift on `space.repair.decline`. space-29 lists a `busy` error (an operation running) for it, but neither `SpaceManager.decline` (space.ts:3324-3338) nor service.ts gates it.

9. Spec wording the proposals collide with:
   - space-31 says "the sync's transient state persists nowhere"; #16 and #24 propose Git's own refs and reflogs, not a new Spex file.
   - space-61 holds the wait "for the app's run alone" (#9).
   - space-21, space-11, space-29, space-31, projects-10, space-59, space-60 and storage-14 each state a gate or lease that rows 1-6, 21, 27, 28 and 34-37 remove.

10. Reviewed and left out because they are neither gates nor mirrors:
    - `RepositorySync.operation` (space.ts:605; `stop` awaits it at shutdown, 1265-1268)
    - `publishing`/`republish` broadcast coalescing (1968-1969, 3551-3562)
    - `stopping` (2016) and `startRead` (1996)
    - everything in `space-groups.ts`: pure functions over a `HostView`, where `mapLimit` only caps how many host reads run at once
