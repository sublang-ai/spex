# 状态根目录锁：故障背景与方案建议

**状态：**方案方向已初步通过（2026-09-29）；两个仓库的实现及规范仍待审查。项目负责人已为状态根目录租约选择方案 A，将 Playbook 会话租约及仓库 claim 纳入范围，并选定复用现有 `hostname` 字段写入带标记的身份、两种平台共用 XDG 风格的身份位置，以及旧所有者沿用同主机名且 PID 已死亡时的接管规则。对最新代码的检查又发现 Spex 根目录租约必须按准确所有者安全回收。发布时按 Playbook [release-35](../../playbook/specs/packages/release.md#release-35) 和 Spex [DR-088](../specs/decisions/088-playbook-17-slc-0-12-cligent-0-27-adoption.md) 的原则，协调升级所有共用存储的写入者；身份文件的上游细节仍待 Playbook 审查。

## 目的与范围

Spex 需要两种不同范围的单实例保护：

- 桌面外壳使用 Electron 的 `requestSingleInstanceLock()`：再次启动同一个桌面应用时，聚焦已有窗口（[app-shell-2](../specs/packages/app-shell.md#app-shell-2)、[实现](../apps/desktop/src/main.ts)）。
- 核心的状态根目录租约：对于 Spex 自有文件，同一时间只允许一个核心或主目录级存储操作，包括桌面核心、服务端核心以及会修改该目录的存储命令（[DR-036](../specs/decisions/036-file-state-store.md)、[core-service-61](../specs/packages/core-service.md#core-service-61)、[storage-14](../specs/packages/storage.md#storage-14)）。Playbook CLI 写入会话文件时使用独立的逐会话租约，可以与核心同时运行。Electron 的应用锁无法覆盖这些主目录级写入者。

本提案比较**状态根目录租约**的几种保护方式，同时审查 Playbook 逐会话租约及仓库 claim 中相关的主机名／PID 问题。修复需要 Playbook 和 Spex 两个仓库协同修改；`slc` 不参与租约或机器身份机制。
已接受的约束是每个状态根目录同时只能由一个核心服务；具体采用 `.lock/owner.json` 是当前实现选择。

## 故障与观察到的行为

2026-09-28，`npm start` 完成构建并启动桌面应用，但核心启动时报错：`/Users/kgm/.spex` 被 `Minion.local` 上的进程 `25313` 占用。
已有的 `.lock/owner.json` 记录了该 PID 和主机名，但进程 `25313` 已不存在。
当时 `hostname()` 返回 `Mac.lan`，而这台机器的本地主机名为 `Minion`。
用户通过将 `.lock/` 重命名为带时间戳的备份，再运行 `npm start`，使应用成功启动：

```bash
mv ~/.spex/.lock ~/.spex/.lock.stale-$(date +%Y%m%d%H%M%S)
npm start
```

这一步保留了旧的所有者记录，同时让原 `.lock/` 路径不再存在；这次成功重试属于人工恢复，并非程序自动回收残留锁。
`.lock.stale-*` 备份会被主目录的 Git 规则忽略；不再需要它排查问题时，可以删除。

2026-09-29，用户还观察到：

| 退出或重启方式 | 观察结果 | 现有代码中的原因 |
| --- | --- | --- |
| 关闭应用窗口 | `.lock/` 消失 | `window-all-closed` 调用 `app.quit()`；`before-quit` 等待 `shutdown()`，后者停止核心并释放存储租约（[桌面主进程](../apps/desktop/src/main.ts)、[核心停止流程](../packages/core/src/service.ts)、[存储关闭流程](../packages/core/src/store.ts)）。 |
| 在运行 `npm start` 的终端按 Ctrl+C | `.lock/` 可能残留 | 源码启动脚本向独立的 Electron 进程组发送 `SIGINT`。Electron 主进程没有将该信号转为 `app.quit()` 的处理器，因此进程可能在异步关闭流程完成前结束（[启动脚本](../scripts/desktop-runner.mjs)、[桌面主进程](../apps/desktop/src/main.ts)）。 |
| 带着残留的 `.lock/` 重启 | 有时仍能成功 | 如果记录的主机名等于当前 `hostname()`，且 PID 已不存在，核心会移走旧目录并重试获取锁；如果主机名不同，则在检查 PID 前直接拒绝（[存储租约](../packages/core/src/store.ts)）。另外，若桌面应用仍在运行，Electron 可能先接管第二次启动，使核心根本不会检查此锁。 |

源码能够解释这些现象，但最初那个进程究竟为何退出，目前无法确定。
现有租约只检查 PID 是否存在，不校验进程身份；如果 PID 被系统复用，已退出进程留下的目录也可能被误判为仍在占用。
如果所有者文件无法读取，启动会按保守策略拒绝，并需要人工处理。

## 现有机制及其局限

核心以原子方式发布 `.lock/` 目录，其中 `owner.json` 记录 PID、主机名、获取时间和令牌。
只有令牌仍与自身一致时，核心才会删除该锁。
启动时，它可以回收同主机且 PID 已死亡的锁；遇到不同主机名，则认为无法检查对方进程是否存活。
[存储 Git 命令](../packages/core/src/storage-git.ts)也会占用同一个 `.lock/` 路径，因此更换机制时必须一并处理。
目前这一存储命令只要看到已有 `.lock/` 就会拒绝，包括可以确认本机原持有者已死亡的残留锁；它并未复用核心的回收流程。
核心的回收流程还存在独立的安全缺陷：它立即删除按旧令牌命名的退役目录，因此一个先前读到旧所有者 O 的迟到回收者，可能在另一进程已回收 O 并发布新所有者 N 后，移走并删除 N。当前还缺少严格的所有者字段校验及仅在探测返回 `ESRCH` 时才认定进程死亡的规则：`processAlive()` 将除 `EPERM` 外的错误也当作进程死亡。只更换主机识别方式无法修复这些准入风险（[根目录租约](../packages/core/src/store.ts)、[存储命令的预留](../packages/core/src/storage-git.ts)）。

这个目录可以协调同一文件系统上遵守规则的 Spex 写入者，但进程突然终止后，目录仍会存在。
主机名可能变化；PID 存在也不足以证明原持有者仍持有租约。
此外，如果两台机器各自持有经异步文件同步服务复制的目录，当前机制也无法保证两者互斥；[DR-036](../specs/decisions/036-file-state-store.md)已明确将多机器并发写入排除在范围外。
观察到的 `Mac.lan`／`Minion.local` 差异证明主机名发生了变化，但不能据此确定是哪项系统设置或网络事件导致的。

故障发生时，安装的 `@sublang/playbook` 15.0.0 会话存储（`reference/sdlc/code.playbook/bin/session-store.js`）同样先比较租约所有者的主机名，再探测 PID。
随后按 [DR-092](../specs/decisions/092-playbook-17-1-slc-0-13-cligent-0-28-adoption.md) 升级工具链后，Spex 声明 `@sublang/playbook` `^17.1.0`，锁定并已安装 17.1.0；本地 Playbook 仓库也已处于 17.1.0。故障时的 15.0.0 仍作为历史背景保留。将来验证 PR 时，须使用 Spex 依赖声明和锁文件所记录、已发布且包含新接口的 Playbook 版本（[Spex 依赖声明](../packages/core/package.json)、[锁文件](../package-lock.json)）。
它允许注入 `hostname` 和 `probeProcess`，但 Spex 目前都没有传入，而独立运行的 Playbook CLI 会自行创建存储实例。
只在 Spex 注入稳定身份，会使同一机器上的接管能力退化：Spex 将机器身份写入 Playbook 的 `hostname` 字段后，仍按 `os.hostname()` 比较的独立 CLI 会把它当作外部主机，Spex 也会把 CLI 写的租约当作外部主机。因此，协调升级须让两种写入者在恢复写入共用存储前都已采用 Playbook 的身份约定。
其仓库协调器（`reference/sdlc/code.playbook/bin/repository-effects.js`）也使用主机名／PID 判断所有权。同一次审查还需覆盖仓库 claim 的身份、残留所有者处理，以及现有 claim 的兼容方案。

## 候选方案

无论选择哪一种方案，Electron 的单实例锁都继续处理桌面窗口行为；它不能保护服务端或存储命令。

| 候选方案 | 收益 | 代价与局限 |
| --- | --- | --- |
| **A. 加固现有目录租约：**使用同步主目录之外的共享机器身份，并按准确所有者安全回收，同时保留保守的 PID 恢复规则。 | 无需新增锁依赖即可处理本次主机名变化和根锁回收竞态，并保留 DR-036 要求的其他主机拒绝规则。 | 突然退出后文件仍会残留，PID 复用仍可能导致误拒绝。旧所有者文件、机器身份丢失、永久保留的退役记录以及 Playbook／CLI 协同仍须明确；所有权无法读取或核实时仍须保守拒绝。 |
| **B. 带超时的心跳租约：**定期刷新租约，超过期限就将其回收。 | 无需原生接口；不依赖进程探测即可从已死亡的所有者恢复。 | 仍活着的所有者可能因休眠、暂停或负载过高错过期限，之后与接管者同时写入。单靠超时不能满足“只有一个写入者”的约束；它只能用作诊断线索，或配合另一套权威准入及隔离机制。 |
| **C. 操作系统建议性文件锁：**在本机写入者的整个生命周期内持有非阻塞独占锁。 | 所有者死亡后，操作系统释放本机锁；残留元数据不再阻止下一次本机启动。 | Node／Electron 没有内置 `flock`／`fcntl` 接口；进程内实现需要原生插件，打包辅助程序则要维护另一份二进制。还须覆盖全部写入入口、打包、ABI 重建、描述符继承及旧版本共存。单靠本机操作系统锁既不执行当前根目录的其他主机拒绝规则，也无法修复 Playbook 会话租约。 |

如果选 C，锁目标应放在**可能被同步的主目录之外**，位于稳定的本机文件系统中，按状态根目录的规范化路径区分，权限保持私有。持锁期间保持描述符打开；正常释放时不删除或替换锁目标。必须验证拉起的 agent 子进程不会继承并延长锁的存活。`flock(LOCK_EX | LOCK_NB)` 是 macOS／Linux 上的一个选择，但如何在 Node／Electron 中接入和打包，是选择 C 的前提（[Apple `flock(2)`](https://developer.apple.com/library/archive/documentation/System/Conceptual/ManPages_iPhoneOS/man2/flock.2.html)、[Linux `flock(2)`](https://man7.org/linux/man-pages/man2/flock.2.html)）。

**本次审查已选定的方向（2026-09-29）：**加固现有目录租约（A），让根目录租约、Playbook 会话租约及仓库 claim 共用一个机器身份。PID 存在但可能已复用时，继续保守拒绝；进程启动身份留待后续。B 不足以作为唯一准入依据；C 仅保留为对比方案，不是计划采用的根目录机制。三处机制可以在同一轮实施中修改；下述字段、位置、旧所有者规则及协调升级原则已作为提案方向选定，身份文件的上游细节仍待审查。

**机器身份：**Playbook 须在 macOS 和 Linux 上统一使用按用户划分、权限私有且只存于本机的身份文件，位置在 `$XDG_STATE_HOME/playbook/`；未设置 XDG 时使用 `~/.local/state/playbook/`。独立 CLI、会话存储、仓库协调器和 Spex 无需依赖 Spex 进程就能读取同一身份。确切文件名、原子发布方式、权限及 XDG 位置不可用时的处理须由上游审查。该位置不得跨机器同步：共用身份会让其他机器的所有者被误认为本机。当前 Playbook 配置已位于 Spex 主目录；XDG 是旧配置／会话目录的约定，并非所有 Playbook 文件的当前位置。身份按用户和机器划分，而非按 Spex 主目录划分：同一台机器上的多个主目录按预期共用身份，但各自的根目录租约仍独立。若身份文件不存在，须以独占方式完整发布一份身份，供今后的租约使用。并发创建失败的一方须丢弃自己生成的值，读取胜者发布的完整文件；如果结果尚不完整或不可用，只能在有界范围内重试或保守拒绝，不得覆盖。身份与新生成值不匹配的已有带标记所有者绝不自动回收；拒绝时说明锁路径与原因，人工确认没有写入者后才能恢复。若身份文件内容有效，且已核实它是当前用户所有、非符号链接、仅有一个硬链接的普通文件，上级 Playbook 目录也是当前用户所有且不是符号链接，便可就地将过宽的文件和目录权限分别收紧为 `0600` 和 `0700`，复核后才让写入者启动。不得替换身份值。路径不安全、所有者不符、当前用户缺少访问权限或权限修复失败时，须保守拒绝。若身份文件存在但无法读取或格式错误，不得覆盖或另行生成身份：所有新写入者均须拒绝启动，说明身份文件路径与原因，也不得退回写入 `os.hostname()`。

**所有者字段和旧格式过渡：**本次复用每种所有者记录现有的 `hostname` 字段，不新增键，也不升级格式版本。新写入者在其中写入带版本标记的机器身份，例如 `machine-id:v1:<UUID>`；新读取者只把严格符合标记格式的值识别为身份，并先与本机身份比较，再探测 PID。没有标记的值按旧主机名处理：只有等于当前 `os.hostname()` 且 PID 已确认死亡时才可回收，供新读取器处理已停止的旧写入者留下的记录。主机名不同、PID 存活、探测失败、所有者格式错误或带标记身份不匹配时均拒绝。看似带前缀但未通过完整标记校验的值属于无法核实的所有者，不得按旧主机名处理。示例标记中的冒号不符合通常的互联网主机名语法，因此意外重合的可能性很低；但操作系统主机名接口并不保证历史值遵守该语法（[Linux `gethostname(2)`](https://man7.org/linux/man-pages/man2/sethostname.2.html)、[Apple `gethostname(3)`](https://developer.apple.com/library/archive/documentation/System/Conceptual/ManPages_iPhoneOS/man3/gethostname.3.html)）。旧的非标准主机名若匹配一个有效标记，通常会被拒绝；但若它恰好等于本机身份，读取器可能对外部所有者套用本机 PID 已死亡的回收规则。不变的字段无法排除这种极小概率的歧义；若要求严格保证，就需要在格式上区分。旧格式回退规则也保留现有的同名主机碰撞与主机名变化局限：遇到 `Minion.local`／`Mac.lan` 这样的旧记录仍需人工恢复。升级共用存储前须停止所有旧写入者；不支持新旧版本同时写入。意外发现仍存活的旧所有者时必须拒绝接管；旧程序也可能把新记录的带标记身份视作其他主机而拒绝接管。诊断信息须将带标记的值称为机器身份，不能当作主机名显示。

## 两个仓库的协同修改

实施需要两个相互关联的 PR。每个 PR 先更新本仓库的规范，再完成代码；审查时应把共用的所有者格式和发布顺序作为同一项变更检查。Playbook 负责身份文件及公开接口；Spex 使用该接口，不重复实现文件规则。`slc` 不需要修改。

| 仓库 | 该仓库 PR 中的改动 |
| --- | --- |
| **Playbook** | 增加唯一的**异步**公开机器身份接口，身份按用户划分、只存于本机；接口覆盖首次独占发布、校验、安全地就地收紧权限，以及已有身份不可用时的拒绝。从现有 `prepareSessionPermissions` 中提取共用的异步安全校验规则，供身份文件及目录复用。不得直接对无关路径调用仅适用于会话的 helper，也不得另立判断策略或同步文件操作适配。让独立 CLI、会话存储和仓库 effect 协调器在各自的异步启动或获取流程中默认使用该身份，同时保留显式主机名与进程探测注入供测试使用。按既定旧格式规则读取无标记所有者，诊断时正确标记机器身份。原会话及配置迁移不得删除身份文件或其上级目录。更新 Playbook 自有的决策、`specs/packages/session-storage.md`、`specs/packages/playbook-cli.md` 和 `specs/packages/release.md` 约束及集成验证。 |
| **Spex** | 先更新其决策以及核心、存储和桌面外壳约束：修订 [core-service-61](../specs/packages/core-service.md#core-service-61)，核对验证它的 [core-service-63](../specs/packages/core-service.md#core-service-63) 是否需要同步修改，保留 [storage-14](../specs/packages/storage.md#storage-14) 的写入者约束，修订 [storage-10](../specs/packages/storage.md#storage-10) 的命令拒绝措辞，并增加存储命令回收本机死亡所有者的行为条目。将 Playbook 依赖下限及锁文件更新到已发布的接口版本。先在异步启动或命令入口取得 Playbook 身份，再注入同步的 `Store` 和根目录租约预留流程；覆盖 `CoreService.start`、存储 Git 的 select／validate／rebind，以及演示和测试初始化。让 `Store` 和 `reserveStorageHome` 共用一套根目录租约获取／释放实现，严格校验所有者和路径，仅在探测明确返回 `ESRCH` 时认定进程死亡，将准确所有者移至 `.lock.retired/<token>/`，永久保留其中的所有者文件，移走后复核所有者令牌，并在发布前检查目标路径，拒绝已有条目。格式错误或没有令牌的根目录所有者均视为无法核实，不得自动回收。存储命令也按同一规则恢复可确认死亡的本机根目录所有者。更新目录化的拒绝提示及中英文翻译；通过有界的正常关闭处理桌面终止信号，同时保留 Node ABI 恢复（[根目录租约](../packages/core/src/store.ts)、[存储 Git](../packages/core/src/storage-git.ts)、[桌面主进程](../apps/desktop/src/main.ts)）。 |

Playbook 现有的会话租约和仓库 claim 已保留令牌专属退役路径，并核对移走的所有者令牌。共用机器身份只改变它们对主机的判定，不扩大仓库 claim 的范围：在 `git init` 之前，预期工作树的 claim 仍按 Playbook 的 `playbook-cli-57` 只在进程内生效。Spex 当前根目录租约却会删除退役路径；替换实现必须永久保留**内含 `owner.json` 的非空**退役目录，防止 POSIX `rename` 将继任者覆盖到空目录上。回收死亡所有者与正常释放均须将准确的活动 `.lock/` 重命名为令牌专属退役路径，再读取移走的所有者并复核令牌，方可完成退役；令牌不符时须保守拒绝，且不得删除移走的路径。任何回收前须严格校验根目录所有者的结构、路径、PID、令牌及探测结果。意外出现的空 `.lock/` 属于格式错误，应保守拒绝；发布时不得替换已有的活动所有者，正常释放也不得移走继任者。

Spex 根目录退役记录放在 `<状态根目录>/.lock.retired/<token>/`。退役前创建并校验权限私有、非符号链接的 `.lock.retired/` 上级目录；令牌对应的目标路径若已存在，须拒绝替换。每个退役目录及其中的 `owner.json` 都永久保留，包括正常释放后；不得自动清理，因为任何有限的时间阈值都无法证明迟到的回收者已经停止。现有的 `/.lock*` Git 忽略规则和可移植文件过滤均排除这一路径。

将已写好所有者文件的准备目录重命名为活动 `.lock/` 前，须不跟随符号链接地检查目标条目。只有明确得到 `ENOENT` 才可尝试发布重命名。若已有条目，即使是空目录或悬空符号链接，也不得覆盖；已有所有者按共用租约规则判断，格式错误或无法核实时保守拒绝。其他检查错误同样拒绝。如果另一名遵守规则的写入者在检查与重命名之间发布了非空活动目录，后续重命名会失败；竞争者须重新核对所有权或拒绝，不得修改受保护状态。

Playbook 的公开身份接口采用异步方式。Spex 在构造同步的 `Store` 前先取得身份并通过选项注入；存储 Git 的异步 select 和 validate 流程也应在调用 `reserveStorageHome` 前取得身份，rebind 及演示入口须遵循同一约定。Playbook 的会话存储和仓库协调器工厂函数可以保持同步，只要在其异步准备或获取流程中解析身份即可。确切文件名、原子发布及持久化顺序、XDG 位置不可用时的处理，以及权限检查原语，仍由 Playbook 审查。Spex 继续仅以 `sessionsDir` 创建会话存储，也不自行创建 Playbook 的仓库协调器。

**PR 与发布顺序：**两个 PR 可以同时提出以便协同审查。开发 Spex PR 时可以临时链接或打包未发布的本地 Playbook。先合并并发布 Playbook 的公开身份约定；Spex 随后更新到该已发布版本，从干净安装刷新锁文件，使用发布包运行集成／系统验证，再合并 Spex PR。合并与发布的依赖顺序不同于用户侧迁移步骤：新写入者向共用存储保存内容之前，须停止所有旧版 Playbook 和 Spex 写入者，按 [DR-088](../specs/decisions/088-playbook-17-slc-0-12-cligent-0-27-adoption.md) 备份主目录，然后升级所有共用该存储的应用。本提案将 Playbook [release-35](../../playbook/specs/packages/release.md#release-35) 的协调升级原则用于本次身份变更：不支持新旧版本同时写入。新读取器仍须按上述规则处理已停止的旧写入者留下的记录，并拒绝意外发现的存活旧所有者。发布说明应交代此升级流程，以及主机名已变的旧记录如何人工恢复。Spex 合并前必须用锁文件记录的已发布 Playbook 版本验证，不能只验证本地检出版本。

**留待后续的进程身份：**现有 PID 复用会造成保守的误拒绝，而不是允许第二个写入者。本轮不增加进程启动字段，也不会仅因存活的 PID 可能已被复用就回收所有者。今后加入该字段可改善恢复，但 Node 没有可移植的启动时间探测：Linux 需读取 `/proc`，macOS 需使用 `ps` 或 `sysctl` 等平台探测。Playbook 的会话租约和仓库 claim 所有者记录都会拒绝多余字段，因此届时需要带版本的所有者格式和兼容方案；Spex 当前根目录读取器不校验精确键集合，但旧版 Spex 仍会比较 `hostname` 字段。

桌面应用还可以单独处理 `SIGINT`／`SIGTERM`，请求 `app.quit()` 以便 `before-quit` 停止核心；源码启动脚本则设置有界等待和升级终止。无论最终选择哪一种租约方案，这都能改善关闭流程，但仍须保证强制终止后的安全（[桌面主进程](../apps/desktop/src/main.ts)、[启动脚本](../scripts/desktop-runner.mjs)、[Electron 应用 API](https://www.electronjs.org/docs/latest/api/app)）。按照此前“审查后再开发”的要求，此项属于**获批后可独立实施**的工作。

上述方案都无法让未经协调的异步文件同步安全地支持跨机器同时写入。真正的多机器并发访问需要权威的单一写入者，或能强制执行写入所有权的分布式协调机制。

## 已确定的边界与仍待审查的细节

- **其他主机的处理规则：**DR-036 要求同一时间仅一台机器写入，且不得清除其他主机的会话租约。采用 A 时，除非用新决策修订 DR-036，也须保留根目录对其他主机所有者的拒绝规则。带标记身份用于区分机器；仅旧记录在同主机名且 PID 已死亡时沿用原有判断方式及其已知局限。
- **本机的主要机制：**根目录租约已选择 A，三处机制共用一个机器身份，本轮不加入进程启动身份。两种受支持平台均采用 Playbook 的 XDG 风格状态目录，但上游仍须确定创建方式及仅存本机的保障措施；对于可能被复用的存活 PID 继续保守拒绝。
- **根目录租约安全：**Spex 须独立于主机名修复迟到回收者竞态，在 `.lock.retired/<token>/` 永久保留含 `owner.json` 的非空退役目录且不得清理，重命名后复核移走的所有者令牌，校验所有者结构与私有路径，并仅将 `ESRCH` 视为进程死亡的证明。正常释放也须遵守同样的重命名规则。发布前不跟随符号链接地检查活动路径，只有路径不存在时才可重命名；活动目录为空或根目录所有者缺少令牌均属格式错误，保守拒绝。核心与存储 Git 写入者须共用这些规则。
- **Playbook 协同：**这需要 Playbook 和 Spex 两个仓库协同修改：Playbook 提供唯一的异步公开身份接口，让 CLI、会话存储及仓库协调器默认使用；Spex 在同步获取根目录租约和存储 Git 预留之前先解析身份。应先发布 Playbook 的约定；新版本开始写入共用存储前，须停止旧写入者并升级所有应用。只在 Spex 注入 `hostname` 会破坏与旧 CLI 之间的同机接管。旧会话迁移及清理时须保留身份文件及其上级目录。
- **兼容与身份：**新记录复用 `hostname` 写入带版本标记的身份；已停止的旧写入者留下的无标记记录，保留同主机名且 PID 已死亡时的回收；其他主机、存活所有者、格式错误、看似带前缀但无效或无法核实的所有者继续保守拒绝。本机身份文件缺失后，不能据此回收身份不匹配的带标记所有者；文件存在但不可读或格式错误时不得自动替换，且写入者不得启动。经核实安全的身份文件或 Playbook 目录若权限过宽，应收紧并复核；所有权或路径不安全时仍保守拒绝。历史上的非标准主机名若恰好等于本机标记，仍是字段不变带来的小概率歧义。旧程序可能将带标记的所有者视作其他主机而拒绝；不支持新旧版本同时写入。留待后续的进程启动字段会被 Playbook 当前的两种所有者读取器拒绝，但 Spex 当前根目录读取器并不校验精确键集合。规范化根目录身份，并处理符号链接和不同路径写法。
- **写入及关闭流程覆盖：**包括桌面、服务端、存储 Git 命令、迁移流程和会话写入者；定义桌面应用的正常信号关闭及有界升级终止，同时保留 [app-shell-26](../specs/packages/app-shell.md#app-shell-26) 要求的 Node ABI 恢复步骤。
- **诊断信息：**区分本机存活所有者、已确认死亡的本机所有者、其他机器身份或旧主机名、无法核实的所有者、身份文件缺失，以及文件不可读或格式错误；不能把带标记身份显示成主机名，拒绝时须报告锁路径和原因。Spex 的根目录拒绝提示来自消息目录；修改措辞时须增加新消息 id，并补齐英文和中文 PO 条目（[DR-078](../specs/decisions/078-the-interface-speaks-the-readers-language.md)）。
