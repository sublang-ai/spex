# App 0.9.0-beta.4 release preparation

Prepared 2026-09-30 for `app-v0.9.0-beta.4`, the fourth beta on the way to 0.9.0 ([DR-087](../../specs/decisions/087-beta-app-releases.md)), covering desktop and server as source.
A beta gates on CI, the smoke and the live smoke, and runs neither the regression nor the manual checklist ([release-26](../../specs/packages/release.md#release-26)).
The [release rules](../../specs/packages/release.md) remain the gate authority.

## Review

Since `app-v0.9.0-beta.3` the range adds one merge of one change, a player's subagent model ([DR-093](../../specs/decisions/093-a-players-subagent-model.md)):

- `subagentModel` is a fourth tuning field beside model, effort and fast mode — on the Captain's and each player's block, on a role binding as a pin, `false` or omission, and in a session's own agent settings, applied at the Captain's block, each tuned player's block and every binding naming a tuned player.
  It is offered wherever the model is — the shared agent editor, the role-binding editor and the session agent editor — where the adapter serves one or a value stands, its empty value reading "Provider default" alone; the chip does not read it.
- Cligent 0.29 enforces and phrases it: on Claude, every subagent of a run uses the named model (`CLAUDE_CODE_SUBAGENT_MODEL` with `CLAUDE_CODE_SUBAGENT_MODEL_FORCE=1`), and one delegation directive naming it is composed into the run's system prompt; Playbook 17.2 carries it as tuning, erased from the structural projection.
  The core requires Cligent `^0.29.0` and Playbook `^17.2.0`; protocol 18.
- Two corrections found on the way: a session's stored tuning no longer masks a structural-drift refusal on continuation, and a player's fast mode now reaches the roles bound to it without their own override, as the launcher resolves it.

The changelog's `[Unreleased]` section carries the entries; as for every beta, it gains no section of its own, so this beta's notes are that section at the tag, the earlier betas' notes included ([release-27](../../specs/packages/release.md#release-27)).

## Upgrade boundaries

Those of `app-v0.9.0-beta.3` stand ([its record](0.9.0-beta.3-preparation.md)); this beta adds two.
A session record that carries a subagent model cannot be opened by Playbook 17.1 or earlier, so every host sharing a Spex home upgrades together; a record without one opens under both.
slc 0.13 still declares Cligent `^0.28.0`, so the root's `overrides` entry points the compiler's Cligent at the app's `^0.29.0` until slc adopts it ([sublang-ai/slc#31](https://github.com/sublang-ai/slc/issues/31)): one engine and one Cligent serve the app and its compiler, and slc's own suite passed against Cligent 0.29 before the override was taken — the sole incompatibility is slc's TypeScript build, which runs no part of the app.

## Coverage this release does not have

The regression is not a beta gate, and it was not run for this beta; its two recorded blockers stand as beta 3 left them ([its record](0.9.0-beta.3-preparation.md)).
The live proof that a player's subagents run on the chosen model is Cligent 0.29.0's own acceptance leg, which observed every subagent frame on Haiku while the main agent's Agent call asked for `sonnet`; Spex verifies that the choice reaches the projection each turn opens on, and runs no subagent of its own ([DR-093](../../specs/decisions/093-a-players-subagent-model.md) §"Verification by layer").
