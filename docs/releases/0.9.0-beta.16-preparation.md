## Purpose and upgrade boundary

This release coordinates bounded session persistence under [DR-132](../../specs/decisions/132-bounded-session-storage.md) and [IR-113](../../specs/intents/113-bounded-session-storage.md).
Playbook 18 keeps the logical recovery and replay contracts while storing new sessions in versioned roots and immutable session-owned chunks.
New manifest, replay, index and content files are bounded to 8 MiB, including an oversized individual JSON value or replay record.
This is a per-file bound, not a total-storage quota, memory bound or retention policy: superseded evidence remains, and existing oversized blobs in Git history are not removed.
Spex selects, validates and publishes each session as one complete family, with dependencies before its root and historical summaries read from the selected revision.

Stop every older CLI and Spex writer and snapshot the shared home before upgrading all writers together.
Earlier writers and direct readers cannot use the new physical format.
Existing monolithic sessions, including schema 7, require explicit source-retaining `playbook migrate-session <id>` conversion before continuation; readable history alone does not authorize recovery.
The ordinary-default import of supported schema 2–6 sessions from the former XDG directory is a separate compatibility path.
