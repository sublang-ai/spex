# App 0.9.0-beta.8 release preparation

Prepared for `app-v0.9.0-beta.8`, covering desktop and server as source.
The [release rules](../../specs/packages/release.md) govern this beta: exact-commit CI, the fresh-install smoke and its live stage are required; the regular-release regression and manual checklist are not ([DR-087](../../specs/decisions/087-beta-app-releases.md)).
The user subsequently requested timely milestone merges and releases only where needed for downstream adoption.
The upstream releases fulfill that dependency requirement; this application milestone will finish on `main` after verification, with a source tag deferred.

## Review

The range from `app-v0.9.0-beta.7` through `11b26017e6b42f0ce1fb631fbb026e7b3ed7eef8` contains 48 commits: 20 ordinary commits and 28 merges.
The review covered every ordinary commit's message, the cumulative source, tests and spec changes, and merge resolutions; no blocking issue remained in that range.
Its notable changes are present in the root changelog:

- Forge lists retain their fetch time, show their age and refresh while visible; failed refreshes preserve the last usable data.
- History uses the last Git commit touching a tracked record instead of a clone's file timestamp.
- The former SQLite store is marked beside the imported file, preventing import into every later fresh home.
- Project creation uses the app's bundled scaffold CLI, pins the project's own copyright identity and gives coding agents a lint command that works without a global CLI.
- Surface shortcuts land focus inside the destination, an open palette retains focus, and the narrow Settings shortcut sheet is keyboard accessible.
- Space forgets the prior remote's synchronization state when the remote changes, offers Join again, and distinguishes empty tracked directories from local-only storage.
- First-run documentation, Chinese terminology and the prior publication record were reconciled with those behaviors.

This release also implements [DR-097](../../specs/decisions/097-media-and-browser-tools-across-hosts.md): file input across conversations, queued intents and authoring; durable native media; managed browser preparation and explicit agent controls; and the ordinary `/inspect` workflow.
It also implements [DR-098](../../specs/decisions/098-live-tool-approvals.md): an authenticated live approval inbox for native working-agent requests, with one-time answers, owner isolation, bounded cancellation, and same-core reconnect recovery.
The later four commits through `8514a150966fccd489ceab87a216ea4bcf020668` add unaccepted design drafts and repair their placement and links; they change no runtime or dependencies.
[PR #63](https://github.com/sublang-ai/spex/pull/63) passed independent review, spec lint and all seven CI jobs.
One existing recovery test initially matched a stale pre-restore event; its failed job passed a single rerun, and this feature strengthens the predicate to wait for the current restore to settle and release its lease.
The final feature and release-preparation commits will be included in the completed range review before tagging.
As required for a beta, the root changelog keeps its non-empty `[Unreleased]` section; no beta-specific changelog section is added.

## Upgrade boundaries

The application protocol advances from 19 to 21 for authenticated attachment transfer, browser preparation, and live approval snapshots and answers.
Reload browser clients when restarting an upgraded server.
Sessions and queued intents now own immutable asset files; copy, back up and select their complete bundles as described in [storage](../storage.md) and [Space storage](../storage-git.md).
Stop older Spex and Playbook CLI processes before the upgraded application writes attachment-bearing history: older writers do not preserve the new asset-bearing records.
Existing configurations are preserved; enable Inspect from the available built-in Library when upgrading an existing home, and configure its working agent in Settings.
Browser preparation proves launch and screenshot on the execution host and does not enable agent access; enabling Browser is a separate explicit choice.
On a headless Linux server, this is an isolated browser on the server, and missing libraries or sandbox prerequisites produce a repairable setup failure without blocking ordinary text work.
An approval answers only an actual pending native tool ask; it does not override native hard denials or grant Codex app-access or operating-system privacy consent.
The live callback route supports Claude, Kimi, and OpenCode; the current Codex exec and Gemini NDJSON transports remain explicitly unsupported for that route while retaining ordinary execution.

## Coverage this release does not have

Native Windows app hosting is outside [DR-049](../../specs/decisions/049-supported-app-hosts.md); Cligent independently verifies its Windows transport and browser contract.
The regular-release regression and manual checklist are not beta gates and are not claimed by this record.
Browser tools do not provide native operating-system desktop control; separate user-supplied tools may provide that capability.
Fresh Spex homes and browser caches do not reset macOS privacy or Codex per-application consent, and this release does not claim a clean-state test of those external grants.
