# App 0.9.0-beta.8 release preparation

Prepared for `app-v0.9.0-beta.8`, covering desktop and server as source.
The [release rules](../../specs/packages/release.md) govern this beta: exact-commit CI, the fresh-install smoke and its live stage are required; the regular-release regression and manual checklist are not ([DR-087](../../specs/decisions/087-beta-app-releases.md)).
The user subsequently requested timely milestone merges and releases only where needed for downstream adoption.

## Upgrade boundaries

The application protocol advances from 19 to 21 for authenticated attachment transfer, browser preparation, and live approval snapshots and answers.
Reload browser clients when restarting an upgraded server.
Sessions and queued intents now own immutable asset files; copy, back up and select their complete bundles as described in [storage](../storage.md) and [Space storage](../storage-git.md).
Stop older Spex and Playbook CLI processes before the upgraded application writes attachment-bearing history: older writers do not preserve the new asset-bearing records.
Existing configurations are preserved; enable Inspect from the available built-in Library when upgrading an existing home, and configure its working agent in Settings.
Browser preparation proves launch and screenshot on the execution host and does not enable agent access; enabling Browser is a separate explicit choice.
On a headless Linux server, this is an isolated browser on the server, and missing libraries or sandbox prerequisites produce a repairable setup failure without blocking ordinary text work.
An approval answers only an actual pending native tool ask; it does not override native hard denials or grant Codex app-access or operating-system privacy consent.
The live callback route supports Claude, Kimi, and OpenCode; the current Codex exec and Gemini NDJSON transports remain explicitly unsupported for that route while retaining ordinary execution.
