# App 0.9.0-beta.26 release preparation

This candidate follows the unpublished beta.25 tag on official main
`d2b5361baf97ef3ebd9fdc19b67c6284c96705b2`. The beta.25 tag is preserved.
Its [full validation run](https://github.com/sublang-ai/spex/actions/runs/41579791450)
had already failed before native release packaging; remaining tests were
cancelled to avoid spending more time on an attempt that could not publish.
No beta.25 installer or release was produced.

## Packaging repair

The native browser acceptance jobs invoke electron-builder from the repository
root with `--projectDir apps/desktop`. The relative hook string was resolved
against cwd, producing a missing root `scripts/verify-packaged-compiler.cjs`.
The earlier local workspace invocation had passed and did not cover this entry.
Both hooks now use the installed private workspace package's module paths;
physical dependency layout and the actual compiler gate remain unchanged.
The gate also uses LinuxPackager's actual executable name for the acceptance
build's override. No app, Agent or compiler business logic is modified.

A small regression uses electron-builder 26.15.3's actual hook resolver in
separate root/workspace processes. Before repair the root failed and workspace
passed; after repair both pass (2 tests), including loading both real hooks.
The Mac ARM64 APP was then built through the root `--projectDir` entry and the
real packaged gate passed: 222 physical declarations, valid FSM accepted,
TS2322 invalid FSM refused, native bundling, engine links and imported output.
The APP was launched and reports 0.9.0-beta.26. The owner continues manual use
on the existing isolated test profile; the installed APP was not overwritten.
No fresh workflow rerun is claimed for this candidate. Prior two real Mac
Codex authoring/compile/Add/invocation flows and the prior complete 6m09s local
release smoke remain separately recorded in the beta.25 preparation record;
no compiler or APP runtime implementation changed after those results.

## Release state and boundaries

The repair, both shell versions, lock metadata and these release notes belong
to one PR. There is no separate version-preparation PR for beta.26.
No runtime or development dependency version is upgraded.

The beta.25 full CI also exposed existing browser/Space/layout failures; the
UI and failing journey files are byte-identical to the official pre-repair
base d26f769d. No unrelated UI fixes are mixed into this candidate.
The owner explicitly authorized limiting this release to required PR checks,
two native builds and packaged strict compiler validation. Only the literal
`app-v0.9.0-beta.26` tag uses selected exact-tag validation instead of full CI;
every other tag retains full CI. Preparation additionally checks that the tag
is on main, matches its second-parent PR tree exactly and that PR head's latest
GitHub Actions `checks` succeeded. Native package failures still prevent release.
Release notes disclose the failed/waived unrelated full UI checks and reused
runtime evidence; no all-UI success is claimed. Fresh full business journeys
are not repeated at the owner's request. No official beta.26 tag, Windows build
or publication is claimed in advance.

The independent explicit CommonJS SLC loader limitation, raw U+2028/U+2029 SDK
limitation and unsigned/not-notarized native packaging remain documented.
Windows native executable-name behavior has not been locally executed on
Windows or Linux; the Mac physical artifact checks do not substitute for it.
