## Upgrade boundaries

Playbook 13.3 or later is required: Retry selects the run's own advertised
recovery action through the runtime, and Drop ends the run through the shell's
give-up, which spends no model call.

`SessionInfo.controls` is removed; `session.control` takes `{ sessionId, kind }`
and the core opens the session before reading it, because a settled parked
session holds no shell (`releaseAtSettle`, [DR-051](../../specs/decisions/051-runtime-held-for-a-turn.md)).

A failure that parked a run now summons until that run leaves its failure
state; a later Boss turn no longer clears it. A failure that parked no run
keeps the rule it had. Dropping is not resumable — Playbook clears the run's
retained generation — and records nothing of its own beyond the run's history.

## Coverage this release does not have

[run-view-132](../../specs/packages/run-view.md#run-view-132) records that the
served harness opens a continued session with no engagement restored. The
browser lane therefore proves that the notice appears and stands through
settlement, that a control the opened run cannot satisfy refuses with its
cause, that Drop's confirm backs out having sent nothing, and that no control's
busy form widens it at 320 pixels — but no automated lane proves a *successful*
Retry or Drop against a real parked run. That path rests on the fixture stream
for the interface's reaction and on the manual checklist row added in `3669122`
for the round trip itself.
