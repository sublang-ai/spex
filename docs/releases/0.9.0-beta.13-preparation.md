# App 0.9.0-beta.13 release preparation

Candidate for `app-v0.9.0-beta.13`, releasing the desktop and server as source.
This preparation starts from main `004797416c24cbf1c186a90c331d3220fcb944fb`, tree `41f0e9db8c7ce23763d5d531d90395f7cbe9a08c`.
The versioned candidate and its final integrated commit are not yet recorded.
The [release rules](../../specs/packages/release.md) require successful CI for the exact tag commit and one fresh official installed smoke with its live stage.

## Changes since beta.12

Beta.12 was released at `9213429`; its preparation record and smoke results remain historical evidence for that release.
The new range contains two implemented fixes:

- PR180 (`85fec623`): Core shutdown fences new session admission, drains already-admitted openings, and retains unresolved cleanup ownership instead of reporting successful cleanup.
- PR181 (`00479741`): explicit content-size push rejection retains saved commits and access, reports instance-only size guidance, and leaves explicit permission refusals ahead of size classification.

PR178 (`779985d3`) proposed the multi-instance and repository-placement designs.
PR179 (`183bd94b`) accepted the multi-instance home specification in DR127; repository placement in DR128 remains proposed.
Both PRs changed specifications only: this beta does not implement multi-instance homes or placements.
The app changelog's nonempty `[Unreleased]` remains the beta's cumulative notes, with no beta-specific version section.

## Candidate scope

This preparation changes only both shell versions, their two workspace lock entries, the app changelog and this record.
Desktop and server carry `0.9.0-beta.13`; the CLI version, dependency resolutions, runtime source and smoke drivers are unchanged.
The release ships source, not packaged binaries, and does not update existing installations.
The size-guidance fix does not increase the instance's storage limit or make an earlier rejected push successful.

The smoke runs build, spec lint, fresh install, packed CLI user journeys and installed live desktop dispatch/abort.
It uses the shipped configuration without provider overrides: the template Captain and coder use Claude Opus 5.5 at high effort.
The live driver observes real coder activity, then aborts and waits for session release, app teardown and native ABI restoration.
The scratch clone, empty npm cache and isolated app state belong to the run; success removes the scratch, while failure retains it.
This gate proves installed dispatch and abort, not a complete CODE delivery or an independent Reviewer run.
The regular-release regression and manual checklist are not beta gates.

CI and smoke for earlier commits do not supply these gates.
The exact final candidate, outcomes, durations, cleanup and signed publication must be recorded from their actual results before release.
