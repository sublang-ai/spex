# T06 — OpenGraphLab

## Who they are

Maintainers of an open-source Rust crate on GitHub; issues, pull requests, CI, reviewer rotation, volunteer budgets.

## Day 2: procedures

`contrib` (implement and verify in one): issue to branch to reviewed commit to pull request, with built-ins `branch` and `pr` for the GitHub side; adopts T02's `verify`.

## Day 3: project

`graph-crate`: a small graph library, created in Spex and pushed to GitHub.

## What happened

- **Day 2.** The representative described `contrib` in the authoring chat: implement a GitHub issue on its own branch in one commit with `cargo test` passing, up to two review rounds by a maintainer, then push and open the pull request. The first compile passed every phase; the roles came out as `Contributor` and `Maintainer`; registration bound them to `dev.coder` (Opus 5.5, medium) and `dev.reviewer` (GPT-6.1 Sol, high).
- **Day 3.** `graph-crate` was created from the palette, pushed to GitHub under the team's account, and issue #1 ("undirected graph with BFS shortest path") was filed. `/contrib #1` implemented the crate on branch `1-undirected-graph-bfs-shortest-path` in one commit, the maintainer round found nothing, and the push step stopped: the machine's Git answered GitHub as another account and `gh` was not logged in (N-02, a setup fault). After the fix, `/pr` refused once more because the authored playbook package sat untracked in the working folder (W-17); once committed, `/pr` pushed, opened pull request #2, waited for checks and merged it. The local `main` was not advanced by the playbook ("updateLocalDefault" exited 1) and was pulled by hand.
- **Sharing.** The `contrib` package was published to the workshop org at the internal registry after two edits a participant would not expect: the org from the login to the workshop's (W-18) and a `license` the manifest lacked (W-21). T09 added it from the registry and enabled it with its own players in one step.
- **Verify (T02's).** Added from the registry and run on `main`: the tester wrote the tests, the traceability matrix and the test report under `docs/verification/` and committed (`ba2a07b`), then audited its own work and committed fixes (`14d6c73`) while saying it was "waiting for the auditor's second round"; the runtime refused the two commits in one step and the run failed (W-25). Dropped; the verification files stand.

## What they found

- W-17: the authored package blocks `/pr` until someone commits it, and nothing says so.
- W-18, W-21: publishing a fresh package fails twice before it works (org, license).
- W-19: the pull request that carried the playbook package added 31,400 lines, most of them the compiler's build cache.
- N-02: a per-team `XDG_CONFIG_HOME` hid the GitHub login from the agents (simulation setup).
