# T08 — Kestrel Data

## Who they are

An eighty-person data and ML platform company; Python; experiment-driven with metric gates.

## Day 2: procedures

`evaluate` (verify): an eval suite per metric, baseline against the change, a report with thresholds, reviewed; `promote` (deploy). Adopts T05's `design`.

## Day 3: project

`eval-harness`: a small evaluation harness, created in Spex.

## What happened

- **Day 2.** `evaluate` was described in chat: an evaluator writes and runs an eval suite against agreed thresholds and the main baseline, commits the suite and a report, a reviewer checks the table and the verdicts until settled. It compiled on the first try; registration bound Evaluator to `dev.coder` and Reviewer to `dev.reviewer`.
- **Day 3.** `eval-harness` was created from the palette and paired into the team's subgroup. The built-in `/code` built the library in three commits over three review rounds (one reviewer note on what "numeric threshold" means). `/evaluate` against four thresholds passed in one evaluator commit (`3e21dc7`) and one review round with no findings: 8/8 tests, 20/20 exact-match agreement, all 33 below-threshold cases flagged, median 0.002 ms per case; the scaffold baseline had nothing to measure.
- **Sharing.** T05's `design` was added from the registry and enabled here with the team's players, as the plan's first stage.
- **Sharing.** `evaluate` was published to the workshop org and T01 added and enabled it from the registry.
- Open: `promote` was not authored, so the last stage is not walked.

## What they found

- Nothing blocking: the English, single-word-role path through authoring, compile, enable and run worked first time.
- W-17: the untracked package folder confused the coder here as everywhere.
