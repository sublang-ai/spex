# T08 — Kestrel Data

## Who they are

An eighty-person data and ML platform company; Python; experiment-driven with metric gates.

## Day 2: procedures

`evaluate` (verify): an eval suite per metric, baseline against the change, a report with thresholds, reviewed; `promote` (deploy). Adopts T05's `design`.

## Day 3: project

`eval-harness`: a small evaluation harness, created in Spex.

## What happened

- **Day 2.** `evaluate` was described in chat: an evaluator writes and runs an eval suite against agreed thresholds and the main baseline, commits the suite and a report, a reviewer checks the table and the verdicts until settled. It compiled on the first try; registration bound Evaluator to `dev.coder` and Reviewer to `dev.reviewer`.
- **Day 3.** `eval-harness` was created from the palette and paired into the team's subgroup. The built-in `/code` built the library in three commits over three review rounds (one reviewer note on what "numeric threshold" means). `/evaluate` against four thresholds passed in one evaluator commit (`3e21dc7`) and one review round with no findings: 8/8 tests, 20/20 exact-match agreement, all 33 below-threshold cases flagged, median 0.002 ms per case; the scaffold baseline had nothing to measure.
- **Sharing.** T05's `design` was added from the registry and enabled here with the team's players, as the plan's first stage.
- **Sharing.** `evaluate` was published to the workshop org and T01 added and enabled it from the registry.
- **Promote.** `promote` was described in chat: a promoter writes a promotion record from the eval report (each metric against its threshold and baseline, the target, a measurable rollback condition) and commits it, a gatekeeper reviews in up to two rounds, then the owner is asked "Promote <change> to <target>?". The agent asked one question (findings still open after round two: end as held without asking) and compiled on the first attempt, in 14 minutes. Its register block did not parse — an unquoted `: ` in the intent line — so the surface showed "Spex could not read this block" with no Register card and the agent was not told until the next message (W-31); registration was done by hand: Promoter → `dev.coder`, Gatekeeper → `dev.reviewer`. Published as `claude-workshop-261011/promote@0.1.0` (package commit `93cf764`). `/promote … to staging` first asked which commit (HEAD was the package commit; answered `544dd11`, the commit the eval report covers), wrote `docs/promotions/544dd11-staging.md` (`1a542d6`), fixed the gatekeeper's two findings (`6a43943`), passed round two and asked "Promote 544dd11 to staging?" — which the Captain reworded into two questions with a stray "Your answer was delivered." — and on yes ended "544dd11 is now promoted to staging as the record describes", the final reply dropping the record path and the commit the inner reply had (W-32). Every baseline read "N/A" from the `/evaluate` report and no reviewer flagged it.
- **Final-build walk (2026-10-12).** `/evaluate Evaluate main at HEAD …`: one relay with two questions (which operation the p95 times; what accuracy means), answered; the evaluator committed `1ae90e1` "evaluate main 6a43943; PASS" (tests 26/26, p95 2.3 µs, accuracy 1.0 against `544dd11`), one review round with no findings, `committed` in 15 minutes. Rough edges: the relay repeated itself; the evaluator folded the playbook package's own tests into "all tests"; it first ran them on a stale global Playbook 13.3.0 that only the reviewer caught; the trailer reads "GPT-6 (coder)" (W-54); W-55 seen.
