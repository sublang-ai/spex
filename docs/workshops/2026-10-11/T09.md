# T09 — 乐游工作室

## 团队

二十五人的独立游戏团队；TypeScript；看板，每周可玩版本。

## 第 2 天：规程

`prototype`（原型）：单角色、不审查、速度优先的实现，超范围时向策划提问；`playtest`（试玩）。复用 T06 的 `contrib`。

## 第 3 天：项目

`match3-core`：三消玩法规则模块，在 Spex 中新建。

## 经过与结果

- **第 2 天。** 代表用中文描述了 `prototype`：单角色（Prototyper）把策划的玩法想法做成可试玩的最小原型并提交，不做代码审查。首次编译在 Spec items 阶段失败（W-11：引用形式的标记须保留英文 `in quotes (>)`），代理自行改写后通过；登记时把 Prototyper 绑定到 `dev.prototyper`（GPT-6.1 Sol，xhigh）。包登记的语言仍是 `en`（W-09）。
- **第 3 天。** `match3-core` 由面板新建（TypeScript）。`/prototype` 一轮完成：8×8 棋盘、六种宝石、交换与回退、消除、下落补齐和连锁计分，命令行试玩脚本，9 项测试，提交 `184fad9`；代理注意到工作目录里有未跟踪的 `spex-packages/`，刻意绕开（W-17）。
- **共享。** `prototype` 包发布到内部注册表的工作坊组织（先改 org、补 `license`：W-18、W-21）。从注册表添加了 T06 的 `contrib` 并用本队玩家启用，随后用它跑“无可消除交换时自动洗牌”的需求：贡献者先问“提交前的测试要不要从 cargo test 改成 npm test”（T06 的规程把 Rust 的命令写死了），改后 11 项测试通过、审查无意见、提交 `7ecabba` 落在分支上；最后一步因项目没有远程仓库而未开合并请求。项目随后配对到子组 `乐游工作室/leyou-studio`。
- **跨组重铸。** 新建第二个项目 `tripsplit-ts`（配对到同一子组），从注册表添加本队已发布的 `prototype` 和 T05 发布的规约包 `trip-split`（仅规约，无代码）；规约包装进了 spex 仓库克隆却没有导出到工作目录（W-26），只能把路径写进提示。`/prototype` 一轮就按规约用 TypeScript 重铸出结算库（`81439c2`）：货币表、行程、汇率、费用、最少转账结算，测试、类型检查、20 人性能检查和规约 lint 都通过；规约复制进了本项目的 specs/。

## 发现

- W-11、W-09：中文团队写规程时须知道哪些标记保留英文；包的语言仍是英文。
- W-17、W-18、W-21：发布前的三处手工操作（提交包目录、改 org、补 license）。
- W-26：规约包“只能看到路径”才可复用，课程里“重生成或重铸”这一步目前要人手指路径。
- 复用的教训：别队的规程会带着它的技术栈（`cargo test`、GitHub 的 PR）；课程里应讲“把命令和平台写成参数或让 Captain 问”。
